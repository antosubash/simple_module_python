# Diagnostic codes

The framework runs a set of static checks over installed modules at app boot. The full structural/page/i18n suite runs in development (`SM_ENVIRONMENT=development`), prints to stderr, and aborts boot on any ERROR. In non-development environments (anything other than `development`) module discovery is **strict** — entry-point failures, missing/invalid `meta` (the SM001 class of problems), duplicate meta names (SM008) and missing `depends_on` targets (SM030) raise at boot — and the migration check (SM010) fails boot in every environment. An allowlist skips disabled plugins before import only when every item is an explicit `ep:<entry_point_name>` selector; unqualified metadata names require loading all candidates, even in mixed lists. Unknown explicit selectors fail strict discovery and warn in development. See [Discovery](/framework/discovery).

## Levels

- **ERROR** — fails boot in production. Always fix.
- **WARNING** — printed; doesn't fail boot. Fix before shipping.
- **INFO** — informational; safe to ignore but useful signal.

## The codes

| Code | Level | Trigger | Fix |
|---|---|---|---|
| `SM001` | ERROR | Module subclass has no `meta` attribute, or `meta` is not a `ModuleMeta`. | Declare `meta = ModuleMeta(name=..., version=..., ...)` on the class. |
| `SM003` | WARNING | `pages/<name>.tsx` exists but no `inertia.render()` call in any module references the corresponding page key. | Remove the orphan file, or add the matching `inertia.render("<Module>/<name>", ...)` in `views.py`. |
| `SM004` | WARNING | An `inertia.render("<Module>/<name>")` call exists but no matching `.tsx` file is shipped. | Create `pages/<name>.tsx`, or correct the render key. |
| `SM007` | INFO | Module overrides no hooks and contributes no conventional routes or locales. | Delete the module if it's vestigial; otherwise ignore. |
| `SM008` | ERROR in strict discovery/static diagnostics; WARNING in lenient discovery | Two selected modules declare the same `ModuleMeta.name`. Strict discovery raises `InvalidModuleError` naming both distributions; development warns and skips the later entry. Static diagnostics also catch table-prefix collisions. | Rename or disable one; use its entry-point name to disambiguate. Names must be unique across distributions. |
| `SM009` | ERROR | A file under `framework/*` imports from any package under `modules/*`, including dynamic imports with literal names or fixed f-string package prefixes. | Invert the dependency: have the module register a callback into the framework (see `principal_serializer` pattern). |
| `SM010` | ERROR or WARNING | `make doctor` reads `alembic_version` from `SM_DATABASE_URL` and the heads from the project's `alembic.ini` (else `host/alembic.ini`). It warns when the config is missing, the state could not be read, or the database was never migrated. It reports an error when a previously migrated database lacks any head. | Restore the config if missing. Boot requires a readable migration history outside development. Run `make migrate` if behind, or use `/setup` on a never-migrated first run. |
| `SM011` | WARNING | A table in a module's `models` is missing from a database at every head, so no migration creates it. Reported by `make doctor` and, once the database is open, a development boot (also on the Doctor screen). Not checked while the database is behind head. | Generate a revision on the module's branch (`make migration LABEL=<branch_label> msg="..."`, or `uv run smpy migrations new <branch_label> -m "..."`), review it, `make migrate`. |
| `SM012` | WARNING | Module overrides `register_settings` but does not assign to `app.state.<module_lower>`. Dev-only. | Either remove the override or move your state assignment into it. |
| `SM013` | WARNING | Supported locale has no corresponding file in some module's `locales/`. | Add `modules/<name>/<name>/locales/<locale>.json`, or drop the locale from `SM_I18N_SUPPORTED_LOCALES`. |
| `SM014` | WARNING | Non-default locale is missing keys present in the default (untranslated). | Translate the missing keys. |
| `SM015` | WARNING | Non-default locale has keys not in the default (stale / orphan translation). | Remove the stale keys, or add them to the default file if they really belong. |
| `SM016` | ERROR | Locale JSON is invalid or contains non-string leaves. | Fix the JSON; keys must flatten to strings only. |
| `SM017` | WARNING | Optional frontend `package.json` is malformed or its dependency blocks are invalid. | Fix the manifest or remove it when no extra JS dependencies are needed. TypeScript configs are generated by the host. |
| `SM018` | WARNING | An Inertia `router.post/patch/put/delete()` call in a page targets a JSON `/api/*` endpoint, which would return raw JSON and be rejected by Inertia. | Point the call at a view endpoint that returns `inertia.render(...)` or a redirect; or use plain `fetch()` if you really want a JSON response. |
| `SM019` | WARNING | Module declares a non-empty `view_prefix` with conventional views or a `register_routes` override but registers neither menu items nor permissions. | Add `register_menu_items` for a sidebar entry, or `register_permissions` to surface the module in the role editor (sub-pages of another module typically just register permissions). |
| `SM020` | ERROR for conflicts; WARNING for undeclared providers | More than one module declaring `meta.provides_auth=True` remains after auth selection (legacy `_is_auth_provider=True` also counts, deprecated until 0.1.0). Also warns if a module object exposes the `AuthProvider` shape but declares neither; separate implementation objects inside hooks cannot be detected statically. | Select a provider with `SM_AUTH_PROVIDER`, enable only one, or declare `ModuleMeta(provides_auth=True)` on an undeclared provider's module. |
| `SM021` | WARNING | No module declares the auth-provider capability (or the legacy marker). | Install and enable an auth provider (e.g. `simple-module-users` or `simple-module-keycloak`); custom providers declare `ModuleMeta(provides_auth=True)`. |
| `SM022` | WARNING | A module's `styles.css` contains a top-level `@theme`, `@custom-variant` or `@utility` block. That file is imported into `layer(components)`, where those at-rules are inert. | Move the block to the module's `theme.css`, which is imported unlayered so its tokens actually register. |
| `SM023` | WARNING | A module's `theme.css` contains an unlayered plain rule (anything but an at-rule or a `:root`-style selector). Unlayered CSS outranks every Tailwind utility. | Move the rule to the module's `styles.css`, which is imported into `layer(components)` so utilities still win. |
| `SM024` | WARNING | A unique column, constraint or index on a `MultiTenantMixin` table does not include `tenant_id`, so the first tenant to claim a value locks every other tenant out of it. | Make the key per tenant: add `tenant_id` to it (`Index(..., "tenant_id", "slug", unique=True)`). |
| `SM025` | WARNING | `multi_tenant` is on but no module registered `app.state.tenant_resolver`, so only the principal's `tenant_id` claim can bind a tenant — with most auth providers every tenant-scoped query then fails closed. Checked at boot (it needs the built app), in every environment, not by `make doctor`. | Install the `tenants` module, or register your own `async (Request) -> str \| None` resolver on `app.state.tenant_resolver`. |
| `SM026` | INFO | The configured database is SQLite and a module model declares an expression index (e.g. `lower(email)`) that the database does not have by name (every one when the database file cannot be read). SQLite cannot reflect those, so autogenerate and `alembic check` cannot verify them and a clean diff says nothing about them. | Add the index to a revision by hand and verify on PostgreSQL: `make migrations-roundtrip-pg` in this repository, `make migrate` then `alembic check` against a PostgreSQL `SM_DATABASE_URL` in an app. See [Migrations](/module-authoring#reviewing-a-revision-autogenerated-on-sqlite). |
| `SM027` | WARNING | A key in `host/locales/overrides/<locale>.json` matches no catalog key, so the override was skipped. Reported by `make doctor` and at dev boot. | Fix the key: overrides replace an existing key by its full dotted path (e.g. `users.login.aside_heading`). See [i18n](/framework/i18n#overriding-module-copy). |
| `SM028` | WARNING | A module's `tasks.py` imports `torch`, `tensorflow`, `ultralytics`, `osgeo`, `rasterio`, `cv2` or `sklearn` at module level, so every process that loads the module's tasks (web, each worker, beat) pays for it and a queue-restricted worker cannot avoid it. | Import the package inside the task function. See [background_tasks](/modules/background_tasks#running-a-worker-for-a-subset-of-modules). |
| `SM029` | INFO | A module overrides `db_extensions()` (Postgres extensions such as `ltree`) and the configured database is SQLite, which has none. `ensure_db_extensions` raises `UnsupportedDatabaseError` when migrations run. | Point `SM_DATABASE_URL` at PostgreSQL. See [Postgres extensions and column types](/database/extensions). |
| `SM030` | WARNING at a dev boot; ERROR in `make doctor` | A module's `depends_on` names a module that is not loaded (not installed, left out of `SM_MODULES_ENABLED`, or dropped because another auth provider was selected — `keycloak` drops `Users`). Outside development the boot raises `MissingDependencyError` listing every pair. | Install and enable the dependency, or leave the dependent module out. A relationship that is only about order belongs in `optional_depends_on`. See [Discovery](/framework/discovery#modulemeta). |
| `SM031` | WARNING | An `/api` route has no permission, `TokenAllowed` or `Authenticated` gate anywhere in its dependency tree (include-level dependencies count) and no public-route match, so the schema cannot say who may call it. Needs the built app: reported at a **dev boot** (and in the Doctor screen), not by `make doctor`. | Add `Depends(RequiresPermission(...))`, or `Depends(Authenticated())` when any signed-in user may call it, or register it in `register_public_routes`. |
| `SM032` | ERROR (fails boot in every environment) | A `ModuleBase.spa_mounts()` prefix overlaps a module's `route_prefix`/`view_prefix`/`admin_view_prefix`, a `static_mounts()` prefix, a framework path (`/api`, `/admin`, `/setup`, `/i18n`, `/health`, `/static`, `/modules`) or another SPA mount. The mount would shadow, or be shadowed by, that router. | Pick a prefix nothing else uses. See [Legacy SPA mounts](/framework/spa-mounts). |
| `SM033` | ERROR or WARNING | A module data compatibility check found a missing semantic upgrade (a WARNING when the database could not be checked; a SQLite file that does not exist yet is skipped). Token schema/legacy credentials are errors; unmoved mail system keys warn. Errors refuse boot outside development. Never-migrated first runs defer checks. | Follow the module's remediation. If it gives a `smpy migrations prepare` command, review the generated revision and apply `upgrade heads`. See [Upgrading a host](/guide/upgrading). |
| `SM034` | WARNING | A `subscribe_durable(...)` call in a module's package source has no `name=`. The default name is the handler's import path, so moving or renaming the handler strands its undelivered outbox rows (they retry as an unknown handler, then go `dead`). Found by AST scan; `tests/` is skipped. | Pass `name=` with a constant from `constants.py` whose value is the current default name. See [Durable delivery](/framework/events#durable-delivery). |

`SM022`/`SM023` are the two halves of the same invariant: a module's optional [`theme.css` is imported unlayered and `styles.css` into `layer(components)`](/module-authoring#styling), and CSS put in the wrong one silently does nothing (or silently wins everything).

## When diagnostics fire

| Context | What runs |
|---|---|
| App boot in development | Full structural/page/i18n suite, results logged to stderr. ERRORS abort boot. After the routes are wired, SM031 (unguarded `/api` routes) is added; once the database is open and at head, SM011. |
| App boot in non-development | Strict module discovery (raises on SM001-class failures, duplicate names/SM008 and missing dependencies/SM030), auth-provider selection, the migration check (SM010) and SM025 (logged as a warning). The page/locale static suite is dev-only. |

Sample dev-mode output:

```text
running diagnostics …

WARNING SM003  modules/orders/orders/pages/Unused.tsx: no inertia.render("Orders/Unused") call found
WARNING SM013  locale "es" missing file for module "orders" (expected modules/orders/orders/locales/es.json)
ERROR   SM010  Database is behind: missing heads '9f8e7d6c5b4a' — run `make migrate`

1 error, 2 warnings
```

Treat a clean dev boot as the "ready to ship" gate. If you want to run the diagnostics manually without booting the app, the framework repo's `make doctor` target does exactly that — it's a contributor convenience and not part of the user-facing flow.

## Adding a new diagnostic

If you think a rule deserves a code, open a design doc in `docs/plans/` first — existing codes are stable contracts (downstream tooling can grep for them). Use the next free number in the `SM0XX` range and:

1. Add the check to `simple_module_core.diagnostics`.
2. Wire it into `run_diagnostics()` (or the relevant `*Diagnostics.run()` method) so it runs at app boot.
3. Update this page with the row.
4. Add a test case under `framework/core/tests/`.
